## 选择结论与现状证据

选择 **Phase 0 剩余 Layout/Render 每帧运行时埋点**，暂不转入 WP2，理由如下：

1. 权威路线图在“当前主线”“Phase 0”和“量化指标”中均明确该项仍为 `待埋点`，且优先级高于继续推进 WP2。
2. `src/core/TaskChain.hpp` 的 `QueuedTask` 已维护 `globalcontext::FrameContext`，`RenderTask` 固定触发 `UpdateLayout`、`UpdateRendering` 和 `EndFrame`，已有明确常规帧边界可承载计数。
3. `src/systems/LayoutSystem.cpp::update()` 与 `src/systems/render/RenderFrame.cpp::RenderSystem::update()` 尚未发现按 `FrameContext` 归属的 Layout/Render 调用次数指标。
4. `RenderSystem::RenderStats::frameCount` 只在存在脏窗口并真正进入渲染工作后累加，不能表达“每个调度帧收到几次 UpdateRendering”，不足以验收路线图的默认单帧次数。
5. WP2 的阻塞事实仍存在：`src/core/SystemManager.cpp::removeSystem()` 当前直接 `erase`，Manager 也没有显式状态机；但按用户给定优先顺序，应在确认 Phase 0 埋点尚未实现后先完成本包。
6. 未触碰 Animation/Eigen 公共类型迁移。
