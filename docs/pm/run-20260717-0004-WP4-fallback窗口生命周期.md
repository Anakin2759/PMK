## 当前代码核验结论

1. **首选可测试入口是 Application + runtime-bound Factory**：`ui::factory::CreateApplication(std::span<char*>)`/`ui::Application` 会真实执行 `SDL_Init(SDL_INIT_VIDEO | SDL_INIT_EVENTS)`；`ui::factory::CreateWindow(UiRuntime&, ...)` 会创建隐藏的真实 `SDL_Window`，返回含 entity、window ID 与 runtime token 的 `WindowHandle`，并同步触发 `WindowGraphicsContextSetEvent`。无需新增或修改公开 API。
2. **关闭路径可由现有入口确定性驱动**：`ui::utils::CloseWindow(entity)` enqueue `events::CloseWindow`；测试调用 `application->runtime().dispatcher().update<events::CloseWindow>()` 后，`StateSystem::destroyWidget()` 同步触发 `WindowGraphicsContextUnsetEvent`、调用 `SDL_DestroyWindow()` 并销毁 ECS entity。测试不需要运行 `Application::exec()` 或渲染帧。
3. **强制 CPU fallback 会绕过 GPU device 创建**：独立进程 argv 使用 `--backend=cpu`；`AppConfig::forceFallbackRenderer()` 使 `RenderSystem::ensureInitialized()` 直接设置 fallback，跳过 `DeviceManager::initialize()`。当前 build 的 `UI_FORCE_CPU_RENDER=OFF`，因此必须保留运行时参数，不得依赖编译宏。
4. **最低层 fallback 后端可观测但不应成为首选层级**：`FallbackBackendRenderer::initialize(SDL_Window*)` 会调用真实 `SDL_CreateRenderer(window, driver)`；测试可通过 SDL 公共函数 `SDL_GetRenderer(window)` 和 `SDL_GetRendererName(renderer)` 断言实际 renderer 为 `software`，无需生产诊断 API或 GPU mock。
5. **当前 build 具备测试环境**：`build/CMakeCache.txt` 为 `ENABLE_BUILD_TESTS=ON`、`SDL_DUMMYVIDEO=ON`、`SDL_OFFSCREEN=ON`、`SDL_VULKAN=ON`；生成的 SDL build config 同时定义 `SDL_VIDEO_DRIVER_DUMMY` 与 `SDL_VIDEO_DRIVER_OFFSCREEN`。本批固定使用 `offscreen`，不得静默退到 `dummy` 或 `windows`。
6. **现有测试拓扑**：`tests/unittest/CMakeLists.txt` 提供 `configure_ui_test_target()`，现有 executable 为 `ui_unit_tests`、`ui_ecs_tests`、`ui_api_tests`，聚合 target 为 `ui_tests`，均由 `gtest_discover_tests()` 注册。当前没有独立 SDL 生命周期 target，也没有项目测试创建真实窗口。
7. **已识别的生命周期风险**：`RenderSystem::onWindowsGraphicsContextUnset()` 在 fallback 分支直接返回，fallback renderer 会保留到后续窗口初始化或 Application shutdown；而 `StateSystem` 随即销毁 SDL window。100 次循环可能暴露 renderer/window 所有权不同步、重复销毁或悬空状态。该问题不得在本工作包中顺手改生产代码，应停止并拆出最窄修复包。
8. **查找缓存不是强验收面**：`WindowEntityLookup` 提供失效函数，但当前窗口销毁路径未调用它；`FindWindowEntityById()` 会在下一次查询时自校验并擦除陈旧项。主验收使用 registry validity 与 `SDL_GetWindowFromID()`，缓存结果仅可作为附加断言，不据此扩张生产范围。

## 最小实现规格

### 测试模型

单一 GoogleTest case、单一独立 executable、单一 OS 进程，内部顺序循环 100 次：

1. 在任何 SDL video 初始化前固定 `SDL_VIDEODRIVER=offscreen`（CTest 环境属性为主，测试进程内 SDL hint/环境前置校验为防误用）；若已有 video subsystem 初始化，立即失败。
2. 以仅含程序名和 `--backend=cpu` 的独立 argv 调用 `CreateApplication()`。
3. 断言 `SDL_GetCurrentVideoDriver()` 精确等于 `offscreen`。
4. 每轮使用唯一 alias 调用 `CreateWindow(application->runtime(), ...)`；断言 Result 成功、entity 有效、window ID 非零、`SDL_GetWindowFromID(id)` 非空。
5. 通过 `SDL_GetRenderer(window)` 取得真实 renderer，断言非空且 `SDL_GetRendererName(renderer)` 精确等于 `software`。此断言同时证明 fallback 后端已真实初始化，不接受“仅窗口创建成功”。
6. 调用现有 `ui::utils::CloseWindow(handle.raw)`，再只派发 `dispatcher().update<events::CloseWindow>()`；不调用全量 dispatcher update，不运行主循环或 frame submit。
7. 每轮关闭后断言 registry 中 entity 已失效且 `SDL_GetWindowFromID(id) == nullptr`；失败信息必须包含迭代索引、window ID 与 `SDL_GetError()`。
8. 完成 100/100 后销毁 Application；断言 `(SDL_WasInit(SDL_INIT_VIDEO) & SDL_INIT_VIDEO) == 0`，进程正常退出。

### GPU 禁止条件的证明边界

- 运行时强制 `--backend=cpu`，并断言实际 renderer 为 `software`；按当前 `RenderSystem::ensureInitialized()` 控制流，该分支不会调用 `DeviceManager::initialize()`，因此不会调用 `SDL_CreateGPUDeviceWithProperties()`。
- 不设置 GPU backend，不 claim window，不加载 shader/pipeline/command buffer，不触发 `UpdateRendering`。
- 当前无公开、稳定的“GPU device 创建次数”观测入口；本批禁止为该断言增加公开 API、GPU mock 或 SDL call seam。若审计要求运行时计数证明，停止本批并升级，不得以新 mock 绕过约束。

## 最窄替代层级与停止条件

### 替代层级

若 Application + runtime-bound Factory 无法稳定驱动 100 次，唯一允许提出、但不得在本批直接实施的替代是：

- 在独立测试进程中直接构造 `UiRuntime` + `UiRuntimeScope`，真实 `SDL_Init(SDL_INIT_VIDEO | SDL_INIT_EVENTS)`，逐轮直接创建隐藏 offscreen `SDL_Window`，并直接构造/初始化/cleanup `FallbackBackendRenderer`，使用 SDL API验证 software renderer 与窗口销毁。

该层级仍测试真实 SDL/fallback backend，但不再覆盖 Application、SystemManager、StateSystem 和 Factory 生命周期，因此必须作为**降级验收**单独批准，不能宣称完成“Application 窗口生命周期基线”。不允许再向下退化为裸 SDL-only 测试，因为那将不覆盖项目自有 fallback backend。

### 立即停止条件

1. offscreen driver 不能被当前 SDL build 精确选择，且解决需要修改第三方 SDL或全局构建选项；
2. software renderer 在 offscreen window 上不可用，且只能依赖 GPU backend、平台真实窗口或硬件 renderer；
3. 首轮或循环中出现 renderer/window 双释放、use-after-free、hang，且修复不能严格局限于后续单独批准的 fallback owner 生命周期包；
4. 需要公开内部 backend/device 状态、引入 GPU mock/call seam 或修改公开 API 才能断言；
5. 关闭确定性依赖 `Application::exec()`、WP5 帧管线或跨线程事件循环；
6. 需要 shared device lease、lifetime token、GPU wrapper 改签或 WP7 资源上下文；
7. Application 路径连续两次实施/验证失败。此时记录失败索引、SDL error、driver、最小复现，并回到用户决定是否批准最窄替代层级。

## 风险与控制

| 风险 | 等级 | 控制/残留 |
|---|---|---|
| fallback unset 直接返回，renderer 可能保留已销毁 window | 高 | 100 次顺序循环优先暴露；出现崩溃/悬空即停止，另开仅 fallback owner 的生产修复包 |
| SDL 销毁 window 可能连带 renderer，与 owner 后续 cleanup 重复 | 高 | 不用 mock 掩盖；独立进程、逐轮 renderer/window 断言、失败索引和 SDL error 留证 |
| CTest 发现测试通常每个 case 一个进程，但并行测试仍共享显示环境 | 中 | 单独 executable + 单一 case + `RUN_SERIAL` + resource lock + 固定环境变量 |
| `AppConfig` 单例与 SDL 全局状态污染其他测试 | 中 | 新测试不并入现有 executable；回归另起进程执行 |
| 无 device 创建计数观测面 | 中 | 以 CPU 分支静态控制流和 software renderer 运行时证据验收；禁止为计数增加 mock/API |
| 缓存未主动失效 | 低中 | registry 与 SDL window 为主断言；不扩张到缓存修复 |
| 100 次只覆盖顺序单窗口、无渲染帧 | 中（残留） | 明确仅为 fallback/offscreen 生命周期基线，不计作真实 GPU 或 frame submit 验收 |
